## Findings

None blocking.

Residual, not a land defect of the named supervisor events:

- `tengu_bg_roster_parse_failed` official payloads also send `errCode` (I/O parse) and `issuePath`/`issueCode` (schema parse). Landed calls keep `orphaned`/`quarantined` and omit the extra diagnostic keys. Event name is official; extra keys were not paraphrased into a new event.
- `tengu_bg_worker_exit` official can pass `undefined` (`code:H??void 0`, `signal:$`, `procUptimeMs:q`, `outcome:M`, `exitCause:A`). TS coerces via `asMeta(... ?? ''|0)` because `logEvent` metadata is typed. Same keys.
- `tengu_daemon_lease` official `label: J?.label??null`; TS uses `''`. Same `op`/`label` keys.
- `tengu_daemon_start` official `{worker_kinds:Object.keys(bl).length,worker_count:U,origin:K}`. Landed `run.ts` emits the same three keys with `worker_kinds`/`worker_count` as `0` because in-tree supervisor does not yet load the official worker-config object `bl`. Not a renamed event.
