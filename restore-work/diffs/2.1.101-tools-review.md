## Complete FAIL list and suggested TypeScript locations

1. **Tool-not-available explanation is missing.** Unknown tools still receive only a generic error. Add the official built-in-tool/context/subagent explanation helper and append it in `src/services/tools/StreamingToolExecutor.ts` (`addTool` unknown-tool branch), or centralize the helper next to the tool lookup in `src/services/tools/toolExecution.ts` and call it from both execution paths.
2. **POSIX executable lookup still interpolates command text into a shell.** Replace the POSIX branches in `src/utils/which.ts` (`whichNodeAsync` and `whichNodeSync`) with direct executable + argument-array calls (`execa('which', [command])` / `execFileSync('which', [command])`).
3. **A PreToolUse `ask` still bypasses settings deny evaluation.** Refactor `src/services/tools/toolHooks.ts::resolveHookPermissionDecision` so both hook `allow` and hook `ask` call `checkRuleBasedPermissions` before any forced prompt; return deny immediately and send ask/safety results through the normal permission pipeline.
4. **Normal subagents lose dynamically injected MCP tools.** In `src/tools/AgentTool/AgentTool.tsx`, merge/dedupe MCP tools from `toolUseContext.options.tools` with `appState.mcp.tools` before `assembleToolPool` and required-server enumeration.
5. **Worktree child app state lacks a permission directory grant.** In `src/tools/AgentTool/runAgent.ts`, extend the child `toolPermissionContext.additionalWorkingDirectories` with `worktreePath` and `{ path: worktreePath, source: 'session' }` inside `agentGetAppState`.
6. **Sandbox temp directory is created too late.** In `src/utils/Shell.ts::exec`, create the sandbox temp directory before `SandboxManager.wrapWithSandbox`, treat `EEXIST` as success, and establish the sandbox runtime temp environment (`CLAUDE_TMPDIR`) before wrapping.
7. **`mcp serve` advertises schemas its responses do not satisfy.** Match official 2.1.101 in `src/entrypoints/mcp.ts` by omitting `outputSchema` from `tools/list` (or, less directly, provide schema-valid `structuredContent` for every corresponding call result).
8. **Plugin command suggestions still use display names as identity.** In `src/utils/suggestions/commandSuggestions.ts`, key command IDs, usage, exact lookup, and execution from `cmd.name`; keep frontmatter/user-facing name as a separate searchable/display field.
9. **Plugin recursive copy can descend into its own destination.** In `src/utils/plugins/pluginLoader.ts::copyDir`, resolve source/destination once, detect when destination lies under source, and skip the top-level source child containing the destination.
10. **Directory/file marketplace plugins still prefer stale cache copies.** Thread marketplace source through `loadPluginFromMarketplaceEntryCacheOnly` and `loadPluginFromMarketplaceEntry` in `src/utils/plugins/pluginLoader.ts`; for marketplace source `file`/`directory`, load directly from the marketplace source path.
11. **Plugin skills omit `context` and `agent`.** In `src/utils/plugins/loadPluginCommands.ts::createPluginCommand`, add `context: frontmatter.context === 'fork' ? 'fork' : undefined` and a string-normalized `agent` field to the returned prompt command.

## Final conclusion

The assigned 2.1.101 Tools/Permissions/MCP/Plugins scope has **11 current TypeScript gaps** under the four-part FAIL rule. Three assigned behaviors are already represented: Grep stale-rg recovery, Discover installed filtering, and `headersHelper` Reconnect handling.
