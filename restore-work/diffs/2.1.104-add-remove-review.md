# Official 2.1.101 -> 2.1.104 add/remove product review

## Scope and method

- Reviewed every declaration in `2.1.104-index/added-product.json` (5 rows) and `removed-product.json` (4 rows) against the actual official `2.1.101`, `2.1.104`, and, where behavior was real, `2.1.108` bundles.
- There is no 2.1.104 CHANGELOG entry to use as evidence.
- Extracted complete declarations with the TypeScript parser, then compared identifier-alpha-normalized bodies and literal-insensitive body shapes. Supporting extraction output is in `_run104-add-remove/declarations.json`; the extractor is `_run104-add-remove/extract-declarations.mjs`.
- Searched the current TypeScript by behavior, not by minified symbol. No `src/**` files were edited.

## Replacement pairing results

The add/remove lists contain three two-sided replacements and one spurious deletion:

1. `p3z -> g3z`: complete 71-byte bodies are alpha-equivalent (normalized SHA-256 `fd83d617a05756153d0b07ab8bb16ac2da223ff7be4e5bd949741f0f87c9e48a`). Only the minified timeout constant changes name (`iT4 -> rT4`).
2. `UdY -> QdY`: complete 1,310-byte bodies have the same literal-insensitive shape (`2405982fd0336dac16bb1e78dcc47cae490fb70dcdd415a86ebcd8708dd07611`). The only semantic literals changed are package `VERSION` and `BUILD_TIME` from 2.1.101's values to 2.1.104's values.
3. `_AA -> YAA`: complete 393-byte bodies have the same literal-insensitive shape (`edfcf398e494a4afa0d6e989c24a0a9422e091772df37a49fa596c4e27d6cd77`). This is the same onboarding-config update with release metadata substituted.
4. `H96`: not removed. The exact 71-byte declaration is present under the same name at official line 3208 in both bundles; `astdiff inspect` reports a 100% structural match. The deletion row is an index/matcher artifact.

That leaves only `u9_` and `Nv6` as genuine additions. They are two declarations belonging to one byte-level SSE idle-watchdog feature.
