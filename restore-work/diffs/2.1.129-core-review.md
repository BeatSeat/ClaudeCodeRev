## Findings

1. **major (FIXED) — `src/components/PackageManagerAutoUpdater.tsx:198`.** Official `M04` runs the
   upgrade with `cwd: f04.homedir()`:
   `L6(DH,fH,{cwd:f04.homedir(),timeout:300000,env:…})`. Our first landing used
   `execFileNoThrow(file, args, { useCwd: false, … })`, and `useCwd: false` resolves to
   `cwd: undefined`, which means execa inherits the *process* cwd — not the home directory. That
   defeats the reason official picked homedir: `brew` refuses to operate from inside some
   repositories, and the project cwd can be deleted mid-upgrade. Fixed by switching to
   `execFileNoThrowWithCwd(file, args, { cwd: homedir(), … })`.

2. **nit — `src/utils/settings/skillOverrides.ts:88`.** `isSkillNameOnly` (official `xR5`) is
   exported but unused: the listing budget checks `getSkillOverride(cmd) === 'name-only'` inline, and
   official's only `xR5` call site is the REPL `skillTruncationStats` effect (`zS4`), which this tree
   does not have (`skillTruncationStats` appears zero times in `src/`). Kept the export with a
   comment naming the missing call site; the REPL gap is recorded in the ledger notes.

3. **minor (pre-existing, not landed) — `src/components/PackageManagerAutoUpdater.tsx:139`.** Official
   resolves the latest version per package manager:
   `F==="homebrew" ? await dq8(Q??"claude-code", g) : await U3$(g)`. Our TS calls
   `getLatestVersionFromGcs(resolvedChannel)` for both. 2.1.128 had the same split (`Mq8` / `j3$`) and
   this tree already collapsed it, so this is a gap inherited from an earlier hop, not a 129
   regression. Left as-is to keep the hop scoped; recorded in the ledger notes.
