## #7 PowerShell auto-approved in permission mode — LANDED

Official: "PowerShell tool commands can now be auto-approved in permission mode, matching Bash behavior."

### 118 vs 119 permission-mode classifier/deny (PowerShell tool name)

118 `nq="PowerShell"`. After denial-tracking setup, auto-mode (`WPH`) **unconditionally** skips the classifier for PowerShell (no `POWERSHELL_AUTO_MODE` in the public bundle — that flag is ant-only DCE):

```
let O=q.localDenialTracking??f.denialTracking??sg$();
if(H.name===nq){
  if(f.toolPermissionContext.shouldAvoidPermissionPrompts)
    return {behavior:"deny",
            message:"PowerShell tool requires interactive approval",
            decisionReason:{type:"asyncAgent",
              reason:"PowerShell tool requires interactive approval and permission prompts are not available in this context"}};
  return y(`Skipping auto mode classifier for ${H.name}: tool requires explicit user permission`), A
}
if(H.name!==wK&&!Y) try { /* acceptEdits fast-path */ }
```

| token | 118 | 119 |
|---|---|---|
| `PowerShell tool requires interactive approval` | 2 | 0 |
| `tool requires explicit user permission` | 1 | 0 |
| `Skipping auto mode classifier` | 3 | 2 (acceptEdits + safe-allowlist only) |
| `H.name===nq` | 3 | 0 |
| `POWERSHELL_AUTO_MODE` | 0 | 0 |

119 `DK="PowerShell"`. Same site after `Fr$()` denial-tracking: the `if(H.name===nq)` deny/skip is **gone**. PowerShell falls through to acceptEdits + classifier like Bash:

```
let O=q.localDenialTracking??f.denialTracking??Fr$();
if(H.name,DK,H.name!==IK&&!Y) try { /* acceptEdits fast-path */ }
```

`if(H.name,DK,…)` is leftover comma/DCE from deleting `H.name===DK`. Not landed (would be a no-op statement). `IK` is the existing Agent/REPL skip — unchanged.

119 public classifier deny text also names PowerShell download-and-execute inside the existing **Code from External** category (118 had only `curl | bash`):

```
118: e.g. `curl | bash`, deserializing external data …
119: e.g. `curl | bash`, `iex (iwr ...)` / `Invoke-Expression` on remote content, deserializing …
```

`iex (iwr` 0→1, `Invoke-Expression` 3→4. Full category list is **not** in this tree's `yolo-classifier-prompts/*.txt` (those stay the short templates). Ant-only `POWERSHELL_DENY_GUIDANCE` strings remain 0/0 both bundles — **not** ungated. Did not invent a new prompt file.
