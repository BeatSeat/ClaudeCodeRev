## Findings

1. **Fixed (was blocking) — a55 deny-only short-circuit now reproduced** (`src/tools/BashTool/bashPermissions.ts` ~2493–2512).

   Re-extracted bundle `a55` (only `iM7(` call site; only `a55(` consumer is `kL$` too-complex). 140 `X95` was allow-exact-only (no iM7). 141 inserts deny-first + iM7:

   ```
   function a55(H,$){
     let q=b84(H,$);
     if(q?.behavior==="deny")return q;
     let K=iM7(H.command);
     if(K!==null){ Q("tengu_bash_dangerous_rm_too_complex",{}); return IX6(...) }
     if(q===null||q.behavior!=="allow")return q;
     return (q.decisionReason?.type==="rule"?q.decisionReason.rule.ruleValue.ruleContent:void 0)===H.command.trim()?q:null
   }
   ```

   `b84` ≡ `checkEarlyExitDeny` (exact-match `Pw8` then prefix deny). `a55` then:
   - deny → return deny (iM7 skipped)
   - otherwise **always** run iM7; on hit, IX6 ask **overrides** exact-match allow/ask
   - iM7 miss + allow → keep allow only if `ruleContent === command.trim()`
   - else return `q` (ask) or `null` (fall through to `F55` / too-complex ask)

   TS too-complex path now:

   ```
   const earlyExit = checkEarlyExitDeny(...)
   if (earlyExit?.behavior === 'deny') return earlyExit
   // iM7 → IX6 ask
   if (earlyExit !== null && earlyExit.behavior !== 'allow') return earlyExit
   if (earlyExit?.behavior === 'allow') {
     keep allow only when decisionReason.rule.ruleValue.ruleContent === input.command.trim()
   }
   // else fall through to too-complex ask
   ```

   Field-equivalent to `a55`. Product copy says the target **cannot be auto-allowed by permission rules**; bundle implements that; TS now does too. Untracked `$UNSET` is `tooComplex` in `resolveSimpleExpansion`, so `rm -rf $UNSET/*` takes this path (when tree-sitter is authoritative, not `TREE_SITTER_BASH_SHADOW`).

2. **Advisory — outer splitter is `W3`, not `splitCommand_DEPRECATED`** (`pathValidation.ts` ~130).

   Bundle `iM7` iterates `W3(H)`: tree-sitter walk, `hz6={program,list,pipeline}`, skip `QQK` (`&&` `||` `|` `;` `&` `|&` newline) + `comment`, recurse `redirected_statement` children that do not `endsWith("_redirect")`, else `push(_.text)`; length `> Ze$` (1e4) or parse fail → `[H]`.

   TS uses `splitCommand_DEPRECATED`. Inner iM7 steps after that first split are field-identical (see Verified-correct). Canonical `rm -rf $UNSET/*` is a single piece either way; inner `/[;|\n\r]|&&/` split still finds the rm in compounds if the outer splitter returns the whole string. Not an allow-bypass.

3. **Advisory — extra `checkSandboxAutoAllow` iM7 site** (`bashPermissions.ts` ~1880–1888).

   Bundle: `iM7` is **only** called from `a55`; `a55` is **only** called from too-complex `kL$`. Sandbox helpers `N84` / `F55` have no iM7 (140 `A95` / 141 `F55` bodies match aside from minify names). Extra TS site is conservative, not a missing-land.

TS after a55-equivalent goes straight to that ask. `F55` is sandbox auto-allow for analyzable too-complex commands — **not** 141-unique and not an iM7 miss. Same gap existed vs 140 `X95`→`A95`. Conservative (ask instead of sandbox allow). Do not expand this hop to backfill it.
