## Verified-correct

- **Save (`handleSave`) vs official `S`** — verified term by term:

  | official | ours |
  |---|---|
  | `Q=new Set(Array.from(Y.keys(),qH=>qH.name))` locked names | `seen = new Set(Array.from(locks.keys(), s => s.name))` |
  | `c=new Set(Q)` seen starts as locked | same set is reused as `seen` |
  | `if(c.has(qH.name))continue; c.add(qH.name)` dedupe | identical |
  | `t=f[qH.name]??"on"` | `value = overrides[name] ?? 'on'` |
  | `r=z.get(qH.name)??"on"` | `shared = sharedOverrides.get(name) ?? 'on'` |
  | `e=A[qH.name]??r` | `effective = localOverrides[name] ?? shared` |
  | `DH=t===r?void 0:t` | `persisted = value === shared ? undefined : value` |
  | `if(DH!==A[qH.name])l[qH.name]=DH,a++` | `if (persisted !== localOverrides[name]) { toPersist[name] = persisted; writeCount++ }` |
  | `if(t!==e)KH++` | `if (value !== effective) changeCount++` |

  Locked skills are seeded into `seen` before the loop, so they are never written and never counted —
  matching official. The `undefined` value is the delete signal:
  `updateSettingsForSource` merges with a `mergeWith` customizer that does
  `if (srcValue === undefined && object && typeof key === 'string') { delete object[key] }`, so
  `toPersist` containing only the *changed* keys merges into the existing `skillOverrides` rather than
  replacing it — unchanged entries survive, and a value that just restates the project/user setting is
  deleted from `settings.local.json` instead of being duplicated. This is exactly what official's
  `b6("localSettings",{skillOverrides:l})` does.

  Error path: `Failed to save skill overrides: ${error.message}` then `return` (no exit message),
  matching official. Success path calls `clearCommandMemoizationCaches()` (official `nqH()`) and exits
  with `Updated N skill override(s)` / `No changes`.

- **Initial state**: `locks.get(skill)?.value ?? localOverrides[name] ?? sharedOverrides.get(name) ?? 'on'`,
  with `if (skill.name in initial) continue` to skip duplicate names — matches official's
  `Q[c.name]=Y.get(c)?.value??A[c.name]??z.get(c.name)??"on"`.

- **Lock map keyed by the command object, not the name** (official `Y` is
  `new Map<command, lock>` built with `RA5(c,c.name)`) — ours is `Map<SkillCommand, SkillOverrideLock>`.
  This matters because two skills can share a name across sources.

- **`localOverrides` is memoized once** with `[]` deps (official `jy.useMemo(…,[])`), so the baseline
  does not shift under the user mid-dialog.

- **Cycle**: `SKILL_OVERRIDE_CYCLE` is `["on","name-only","user-invocable-only","off"]` (official
  `fh6`), advanced with `(indexOf(current)+1) % length` from `prev[name] ?? 'on'`, and it is a no-op
  when the skill is locked (official `if(Y.has(Q))return`).

- **`OVERRIDE_DISPLAY` vs official `SA5`**: `on` → tick/`on`/success; `name-only` → bullet/`name-only`
  with **no color**; `user-invocable-only` → circle/`user-only`/warning; `off` → cross/`off`/error.
  All four match, including the deliberately uncolored `name-only`.

- **Row layout vs official `bA5`**: locked renders `dimColor` `🔒 ` + `label.padEnd(9)`; unlocked
  renders `color={display.color}` with glyph + space + `label.padEnd(9)`; then a two-space `Text`, the
  command name, then a dim ` · source · ~N tok` with ` · locked by ${lock.source}` appended when
  locked. Matches.

- **Hint text**: `${cycle} to cycle, ${save} to save, / to search, ${sort} to sort, ${cancel} to cancel`,
  matching official's `${R} to cycle, ${C} to save, / to search, ${b} to sort, ${u} to cancel`, with the
  same search-mode and empty-result variants. Keybindings bind `select:accept`→cycle and
  `settings:close`→save, as official.
