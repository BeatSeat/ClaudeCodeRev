## Findings

1. **minor (pre-existing, no landing site) — `src/utils/betas.ts:463`.** Official 129 adds the new
   header to `c9K`, the allowlist of betas an SDK caller may keep on third-party providers:
   `c9K=new Set([S6$,LF8,Yr,R6$,t$H,ex$,C6$,e$H,PF8])`, consumed by `XF$`
   (`if(!EB()) _=K.filter(A=>c9K.has(A)…"SDK beta '…' dropped on 3P")`) and by `l9K`. This tree has no
   such filter — `getAllModelBetas` merges `getSdkBetas()` unconditionally, and the string
   `dropped on 3P` appears nowhere in `src/`. The gap predates this hop, so there is nothing to add
   the header *to*; inventing the filter here would be landing an earlier hop's work under a 129
   commit. Recorded in the ledger notes instead.

2. **nit — `src/utils/plugins/schemas.ts:872`.** Official's `experimental` object carries both
   `monitors` and `themes`. Ours declares only `monitors`, because this tree has no plugin `themes`
   component at all (`themes` in `src/` is the color-theme subsystem, unrelated). The validator still
   warns on a top-level `themes`, matching official copy. Ledger row for changelog item #4 is marked
   `partial` for this reason.

3. **nit — no SSRF guard on `--plugin-url`.** `downloadSessionPluginZip` will fetch any URL the user
   passes, including `http://169.254.169.254/…`. Official `jr1` has the same behavior — there is no
   scheme or host allowlist in the bundle. Flagged for visibility only; matching official is correct
   here, and the flag is explicit user input.

  `loadSessionOnlyPlugins` is a faithful port:
  - signature changed from `string[]` to `{kind:'path'|'url', value}[]`, and the caller builds it as
    `[...paths.map(path), ...urls.map(url)]` in that order (official
    `[...$i().map(D=>({kind:"path",value:D})),...qi().map(D=>({kind:"url",value:D}))]`);
  - serial `for` loop became `Promise.all` over the sources, with per-source
    `{plugin, errors}` results flattened afterwards (official `$.flatMap`);
  - constants confirmed from the bundle: `Dr1=30000` → `PLUGIN_URL_FETCH_TIMEOUT_MS`,
    `Ks$=268435456` → `PLUGIN_ARCHIVE_MAX_BYTES`;
  - the size cap is enforced **twice**, on `content-length` and again on the streamed byte count with
    `stream.destroy(...)`, matching official;
  - download writes `${target}.part` then renames (official `let W=`${z}.part`;…await CA.rename(W,z)`);
  - a failed re-fetch falls back to the cached archive when it exists and rethrows otherwise
    (official `if(!await X_(z))throw J;E(\`Re-fetch … reusing cached ${z}\`,{level:"warn"})`);
